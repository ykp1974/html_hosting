# 株式投資AIエージェント・スクリーニング＆売買シミュレーション改善提案

現在運用されているシステム（React + GAS + スプレッドシート + Python）の強みを活かしつつ、**省力化（自動化）**および**精度向上（スクリーニング・検証の高度化）**を実現するための具体的な改善アイデアとロードマップをまとめます。

---

## 1. システム構成の全体像と進化ロードマップ

### 【現状の構成（Phase 1）】
フロントエンドでの手動操作をトリガーとし、GASやスプレッドシートの関数（`IMPORTXML`など）を介してデータ取得と記録を行う構成。

```
[ React UI ] ──(POST/GET)──> [ GAS / スプレッドシート ]
     │                              ▲
   (手動実行)                    (IMPORTXML等で取得)
```

### 【目指す構成（Phase 2: 省力化 & 精度向上）】
データ取得・チャート分析・アラート判定をPythonバックエンド（GitHub Actions）で自動化し、人間は「通知確認」と「最終的な投資判断・ログ参照」のみを行う構成。

```
[ GitHub Actions (Python) ] ──(データ取得 & 形状判定)──> [ GAS / スプレッドシート ]
     │                                                      ▲
     ├─(条件合致時)──> [ LINE / Discord 通知 ]               │ (データ閲覧・記録)
     │                                                      │
     └─────────────────────────────────────────────────> [ React UI ]
```

---

## 2. 省力化（自動化・運用負荷軽減）の改善案

### ① `IMPORTXML` / Scraping 依存からの脱却（Python一括処理化）
* **現状の課題:**
  * GAS上での `IMPORTXML` や Yahoo!ファイナンスHTMLの正規表現抽出（`match(regex)`）は、Webサイトの仕様変更でスクレイピングが失敗するリスクが高い。
  * スプレッドシート内で多数の数式が再計算されるため、処理が重くなりGASのタイムアウトエラーが発生しやすい。
* **改善策:**
  * 株価・PER・信用買い残などのデータ取得は、Python側（`yfinance` や `jquants-api-client` など）で一括実行する。
  * スプレッドシートには数式ではなく**計算済みの数値**を書き込む仕様に変更し、スプレッドシートを軽量なデータベース（ストレージ）として運用する。

### ② クラウド定期実行（GitHub Actions）による完全自動監視
* **改善策:**
  * 画面（React）を開かなくても、**GitHub Actions** を利用して市場クローズ後（平日15:30〜、または信用買い残更新時の火曜日17:00など）にバッチ処理を全自動実行する。
  * チャート形状の検知（`ChartShapeChecker`）や信用買い残の変動検知が行われた際、**LINE Notify** または **Discord Webhook** へ自動で通知を飛ぶようにする。

---

## 3. 精度向上（スクリーニング・検証高度化）の改善案

### ① テクニカル分析・形状判定のPythonライブラリ移行
* **改善策:**
  * チャート形状判定（ダブルボトム、ボリンジャーバンド超過、移動平均線乖離など）の計算ロジックをPythonの `pandas-ta` や `TA-Lib` に移行する。
  * 株式分割・併合の調整後株価を正確に扱えるようにし、判定誤差を削減する。

### ② 売買シミュレーション（`DecisionLogger`）の高度化
* **改善策:**
  * **費用・スリッページの考慮:** シミュレート時に売買手数料や信用金利、スリッページ（想定価格と実際の約定価格の差）を組み込む。
  * **EXITルール（利確・損切り）の自動追跡:** エントリー時に「利確価格」「損切り価格」「保有上限日数」をログに保存し、日足データと照合して自動で勝敗（PnL）を確定・集計する。

## 4. 次に手を付ける具体的な実装ステップ

1. **データ取得ロジックのPython化 (`main_task.py` 改修)**
   * `yfinance` 等で対象銘柄のデータを一括取得し、条件判定まで行った結果をGASのWeb APIへPOSTするスクリプトを作成する。
2. **LINE / Discord 通知の連携**
   * 条件に該当する銘柄が抽出された場合に、LINEへ通知メッセージを送信する処理を追加する。
3. **GitHub Actions ワークフローの設定**
   * 毎週・毎日の定期実行ジョブ（`.github/workflows/`）を定義し、放置運用を可能にする。
