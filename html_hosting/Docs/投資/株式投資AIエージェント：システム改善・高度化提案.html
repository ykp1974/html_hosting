株式投資AIエージェント・スクリーニング＆売買シミュレーション改善提案

1. システム構成の進化ロードマップ

Phase 1：現状の構成（手動トリガー）

フロントエンドの手動操作を起点に、GASやスプレッドシートの関数でデータ取得と記録を行う構成。

[ React UI ] ──> [ GAS / スプレッドシート ] │ ▲ (手動実行) (IMPORTXML等)

Phase 2：目指す構成（完全自動化）

GitHub ActionsとPythonにより、データ取得からチャート分析、通知までを完全自動化し、スプレッドシートをDBとして活用。

[ GitHub Actions (Python) ] ├─(データ取得 & 判定)─> [ スプレッドシート ] ├─(条件合致)─────> [ LINE / Discord ] └───────────────> [ React UI (閲覧) ]

2. 省力化（自動化・運用負荷軽減）の改善案

① IMPORTXML / Scraping 依存からの脱却

Python一括処理化：yfinanceやjquants-api-clientを用いてPython側で一括データ取得。スプレッドシートには数式ではなく計算済みの数値を書き込み、軽量なストレージとして運用。

② GitHub Actionsによる定期実行

完全自動監視：市場クローズ後や信用残更新のタイミングでバッチ処理を自動実行。条件合致時はLINE NotifyやDiscord Webhookへ即座に通知。

3. 精度向上（スクリーニング・検証高度化）の改善案

① テクニカル分析のPython移行

pandas-taやTA-Libを活用し、チャート形状判定（ダブルボトム、ボリンジャーバンド等）を高度化。株式分割等にも対応し判定誤差を削減。

② 売買シミュレーションの高度化

手数料・信用金利・スリッページの考慮に加え、利確・損切り価格や保有上限日数をログ保存し、日足データと照合して勝敗（PnL）を自動確定。

4. 次に手を付ける具体的な実装ステップ

  1. データ取得ロジックのPython化 (`main_task.py` 改修)：yfinance等で一括取得・判定した結果をGASのWeb APIへPOSTする仕組みの構築。
  2. LINE / Discord 通知の連携：条件抽出銘柄の自動通知処理の追加。
  3. GitHub Actions ワークフローの設定：定期実行ジョブ（`.github/workflows/`）を定義し、放置運用体制を確立。
