# HTMLサマリ作成の自動化案

Oct 22, 2026 · @よしお

## 結論

工程1〜5は、ほぼ自動化できます。人が残す作業は「気になった動画やサイトを専用の置き場に入れる」だけにできます。

おすすめは **専用の「要約待ち」キュー → GitHub Actions（1日1回）→ Gemini APIで動画を直接読んでHTML生成 → 自動コミット → Netlify自動デプロイ（既存のまま）** という構成です。月の費用は数百円程度に収まる見込みです。

ただし工程1の「後で見る」だけは、APIで読み取れないという制約があるため、入れ先を少し変える必要があります（後述）。

## 現在のアプリ構成（確認した内容）

- `Docs/<カテゴリ>/<タイトル>.html` に、CSS込みの単体HTML（1本あたり約15〜30KB）を置く構成です。カテゴリは AI関連、投資、政経、哲学、生活、Keep/… など。
- `npm run build` 時に `scripts/generate-file-list.mjs` が Docs を走査して `public/files.json` を作り、`Docs` を `dist` にコピーします。
- 既読状態は GAS（スプレッドシート）と同期しています。
- つまり **「Docs配下にHTMLファイルを1つ追加してpushする」だけで、一覧への反映まで自動で済む** 作りです。自動化側はHTMLを正しいフォルダに置くことだけを考えればよく、Reactアプリ側の改修はほぼ不要です。

補足として、zipを展開した際に、日本語の長いファイル名が4件「ファイル名が長すぎる」で展開できませんでした。Linux（GitHub ActionsやNetlifyのビルド環境）は1ファイル名あたり255バイト（日本語で約80文字）が上限なので、自動化時はファイル名を60文字程度に切り詰めるルールを入れるのが安全です。今のビルドで該当ファイルが欠落していないかも一度確認をおすすめします。

## 工程ごとの自動化案

### 工程1：リンクの取得（「後で見る」）

YouTube Data API では、2016年以降「後で見る（WL）」プレイリストの中身が取得できません（空が返ります）。回避策は次のとおりです。

| 案 | 内容 | 自動化度 | 手間・注意点 |
| --- | --- | --- | --- |
| A. 専用プレイリストに変える | 「要約待ち」などの限定公開プレイリストを作り、「後で見る」の代わりに保存先にする。APIキーだけで読める | 高 | 保存先を変える習慣だけ。最も安定 |
| B. 共有ボタン → GAS → スプレッドシート | スマホの共有メニュー（iOSショートカット／Androidの共有）から、既存のGASにURLを送ってシートに追記 | 高 | Webサイトも同じ操作で入れられる。既存GASを流用できる |
| C. yt-dlp＋ブラウザCookieで「後で見る」を直接読む | 自分のPC上でログイン済みCookieを使って取得 | 中 | 今の習慣のまま使えるが、PC起動が必要。Cookie流出リスク、規約上グレー、仕様変更で壊れやすい |
| D. 手動でURLを貼る | GitHubのIssueやスプレッドシートに貼る | 低 | 確実だが手作業が残る |

おすすめは **A＋B の併用** です。YouTubeはプレイリスト、Webサイトは共有ボタン→シート、という分担にすると、どちらも1タップで済みます。処理済みのものは、シート側で「済」にするか、プレイリストから外す（OAuthが必要）か、処理済みURLの一覧をリポジトリに持って重複を防ぎます。

### 工程2〜4：要約 → Markdown → HTML

NotebookLMには、個人向けの公開APIがありません（Google Cloudの企業版のみ）。そのため、ここはLLMのAPIに置き換え、**2〜4を1回の処理にまとめる** のが一番効きます。

| 案 | 内容 | 強み | 弱み |
| --- | --- | --- | --- |
| Gemini API（YouTube URLを直接渡す） | Geminiは公開YouTube動画のURLをそのまま入力にでき、映像と音声を読んだうえで要約できる | 字幕の取得が不要。字幕のない動画にも対応。NotebookLMに近い品質 | 公開動画のみ。長尺はトークンが増える（低解像度設定で抑えられる） |
| 字幕取得 → Claude/Gemini APIで要約 | youtube-transcript-api等で字幕を取って、テキストとしてLLMに渡す | 安い。モデルを自由に選べる | GitHub Actionsなどクラウドのサーバーからは、YouTubeに字幕取得をブロックされやすい。字幕のない動画は不可 |
| Webサイト | 本文を取得してLLMに渡す（Claudeのweb fetchやGeminiのURL Context機能） | 簡単 | 有料記事やログインが必要なページは不可 |

HTMLの作り方は2通りあります。

- **LLMにHTMLまで丸ごと書かせる（今のやり方に近い）**：既存のHTMLを1本「デザイン見本」としてプロンプトに入れ、同じ雰囲気で書かせます。見た目は毎回変化します。
- **LLMには構造化データ（タイトル、要点、章立て、表など）だけ出させ、固定のHTMLテンプレートに流し込む**：デザインが統一され、トークンも少なく、HTMLが崩れる心配もありません。

手始めは前者で十分です。デザインのばらつきが気になったら後者に移る、という順番がおすすめです。あわせて、LLMに既存のカテゴリ一覧を渡して **保存先フォルダも選ばせる** と、仕分けの手作業もなくなります。

### 工程5：保存・ビルド・push

Netlifyがpushを検知してビルドする構成は、すでにできています。必要なのは「生成したHTMLを `Docs/<カテゴリ>/` に置いてコミット・pushする」部分だけです。

- **GitHub Actions**：定期実行（cron）か手動ボタンでスクリプトを動かし、生成したHTMLをコミット・pushします。privateリポジトリでも、無料枠（月2,000分）で十分に収まります。
- 1日分をまとめて1コミットにすれば、Netlifyのビルド回数も1日1回で済み、無料枠を圧迫しません。
- 失敗した場合はスキップしてシートに「エラー」と書き戻し、翌日に再試行する作りにします。

## 実行基盤の比較

| 構成 | 自動化度 | 初期の手間 | 運用の手間 | 月額の目安 | 向いているケース |
| --- | --- | --- | --- | --- | --- |
| ① GitHub Actions＋Gemini API | 工程1の投入以外すべて | 中（スクリプト1本とワークフロー1本） | ほぼなし | 数百円以下（1本あたり数円〜20円程度。無料枠内でも動くが、無料枠は入力が学習に使われる） | 本命。PCを起動しておく必要がない |
| ② Claude Codeのスケジュール実行（クラウドのルーティン） | 同上 | 小（指示文とリポジトリ連携だけ） | 小 | Claudeの契約内（追加課金なし） | 余っているClaudeの枠を活用したい場合。HTMLの品質も高い。ただし動画そのものは見られないため、字幕取得が必要で、クラウドからはブロックされることがある |
| ③ ハイブリッド（Gemini＝動画理解、Claude＝HTML生成とcommit） | 同上 | 中 | 小 | Gemini分のみ | 動画の理解はGemini、文章とデザインはClaudeと、得意分野を分けたい場合 |
| ④ 自分のPCでClaude Code＋yt-dlp | 「後で見る」もそのまま使える | 中 | PCの起動が必要 | Claudeの契約内 | 今の「後で見る」の習慣を一切変えたくない場合 |

## おすすめ構成

**第一候補：① GitHub Actions＋Gemini API**

1. 気になった動画は「要約待ち」プレイリストへ。Webサイトは共有ボタンからGAS経由でシートへ（人の作業はここだけ）
2. 毎朝GitHub Actionsが起動し、未処理のURLを取得
3. Gemini APIにURLとプロンプト（今の概要説明資料の観点、デザイン見本HTML、カテゴリ一覧）を渡し、HTMLとカテゴリを生成
4. `Docs/<カテゴリ>/<短縮タイトル>.html` に保存し、処理済みとして記録してcommit・push
5. Netlifyが自動でデプロイし、アプリに新着として並ぶ

プロジェクトのテーマが「Claudeの余剰リソース活用」なので、**③のハイブリッド**も有力です。Geminiで動画を要約したMarkdownだけを作り、HTML化とcommitはClaude Codeのスケジュール実行に任せれば、Claudeの枠を活かしつつ、字幕取得の不安定さも避けられます。

## 進め方（実装する場合）

- 最初は「1本のURLを渡すとHTMLが1本できる」スクリプトだけを作り、今のNotebookLM版と品質を比べる
- 品質に納得できたら、キュー（プレイリスト／シート）の読み取りと、GitHub Actionsでの定期実行を追加する
- 必要なもの：GitHubリポジトリへのアクセス、Gemini APIキー（Google AI Studioで無料発行）、YouTube Data APIキー（プレイリストを読む場合）
